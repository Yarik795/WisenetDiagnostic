01 / Описание

Суть, цели и задачи проекта

Платформа проактивного контроля исправности технических средств охраны — от видеонаблюдения и СКУД до биотерминалов и СОТС — с единым центром данных и управленческой отчётностью для руководителя ТСО.

Цель. Дать руководителю ТСО единую оперативную картину состояния систем безопасности на объектах банка — без ручной сборки отчётов из разрозненных источников.

Задачи:

  • Централизовать данные из АС Арсенал, Naumen, Портала Поставщика, SmartView и CMDB в единой базе
  • Автоматически опрашивать оборудование по API (изначально — реестр из CMDB) и классифицировать исправность по категориям «светофора»
  • Формировать управленческие отчёты: мониторинг, оплата работ, повторные РВР, инвентаризация
  • Применять LLM для анализа повторных заявок и интерактивного запроса данных на естественном языке
  • Обеспечить гибкое добавление новых отчётов из комбинации данных разных систем
Целевая аудитория
  • Руководитель ТСО — сводная картина по объектам, тренды, контроль СТК
  • Инспекторы отдела ТСО — быстрая диагностика неисправностей
02 / Проблематика

Данные разрознены — решения запаздывают

Руководитель ТСО ежедневно работает с пятью системами, каждая из которых хранит свою часть картины. Форматы отчётов не унифицированы, единого подхода к представлению данных нет.

АС Арсенал
Паспорта объектов, состав систем САПС/СОТС/СКУД
Naumen
Заявки на ремонт, описания неисправностей
Портал Поставщика
Заявки ПП, статусы оплаты работ СТК
SmartView
Мониторинг видеонаблюдения, состояние NVR
CMDB
Реестр оборудования, IP, адреса, модели
Process AS IS
  • Руководитель собирает сводку вручную из 3–5 выгрузок Excel
  • Нет единого «светофора» исправности по объектам
  • Повторные РВР выявляются постфактум, без системного анализа
  • Статус взаимодействия с СТК виден только в одной системе
  • Добавление нового отчёта — недели согласований и разработки
Последствия для бизнеса
  • Запаздывание реакции на неисправности критичных систем
  • Повторные выезды и оплата некачественно устранённых дефектов
  • Риски при расследовании инцидентов безопасности
  • Невозможность оперативно масштабировать аналитику на новые регионы
03 / Решение

Единая база — все отчёты из одного источника правды

Платформа импортирует данные из пяти систем, нормализует их в единой базе данных и строит дашборды и отчёты, которые отражают реальное состояние ТСО и статус работ с подрядчиками.

Ключевой раздел

Сводный дашборд руководителя

На одном дашборде видно состояние всех систем ТСВ, СКУД и биотерминалов по объектам банка — без переключения между разными АС и ручных сводок. Единый «светофор» по категориям показывает, где видеонаблюдение, контроль доступа и биометрия в норме, а где требуется внимание. Проблемные объекты поднимаются наверх.

  • ТСВ, СКУД и биотерминалы — на одном экране по каждому объекту
  • Группировка по объектам эксплуатации
  • Автоматический опрос каждые 5–15 минут
  • Email-сводка с трендом за 7 дней
Мониторинг инфраструктуры

Диски, температура, время и архив

Отдельно и детально видно состояние всех жёстких дисков, температуру регистраторов, синхронизацию времени и текущую глубину архива по всему парку оборудования.

Если есть отклонения — они автоматически попадают в отчёт, который формируется платформой и направляется на почту. Руководитель и инспекторы получают актуальную картину без ручной проверки каждого регистратора.

  • Контроль HDD, температуры, NTP и глубины архива
  • Автоформирование отчёта при отклонениях
  • Плановая email-рассылка с HTML-вложением
Инвентаризация

CMDB → опрос по API → актуальный реестр

Изначально данные по устройствам берутся из CMDB. Затем оборудование опрашивается по API, и на основе фактических ответов формируются данные для инвентаризации: видно, что нужно убрать из CMDB как устаревшее или ошибочное, и что добавить — реально установленное, но не учтённое в реестре.

Текущая архитектура позволяет подключить любое оборудование с API — Dahua, Hikvision, iFlow и другие производители. Достаточно описать транспорт опроса; бизнес-правила здоровья остаются едиными для всего парка.

Ключевой раздел

Статус оплаты и взаимодействие с СТК

Отчёт по заявкам Портала Поставщика: модернизация и РВР. Контроль оплаты работ подрядчиками, фильтрация по территориальным банкам, экспорт в HTML и email.

  • Данные из Портала Поставщика + Naumen
  • Разделы «Модернизация» и «РВР» с графиками
  • Автоматическая рассылка отчёта на почту
04 / Инновационность · LLM

Искусственный интеллект в ядре аналитики

Проект использует LLM: для автоматического анализа повторных РВР с формированием свода проблем и для интерактивного чата с базой данных на естественном языке. Запросы к модели отправляются пакетами в JSON, ответы парсятся и включаются в отчёты.

LLM · Анализ РВР

Анализ повторных РВР

Отчёт выявляет объекты с повторными заявками на ремонт. LLM анализирует тексты заявок из Naumen и Портала Поставщика, присваивает вердикты и формирует общий свод проблем на объектах.

Проблемные объекты подсвечиваются цветными бейджами — руководитель сразу видит, где качество устранения неисправностей вызывает вопросы.

confirmed — повтор подтверждён suspect — подозрение possible — слабые признаки none — повтор не подтверждён
  • Запросы к LLM отправляются пакетами (чанками) в формате JSON; ответ парсится и сохраняется в отчёт
  • Кэширование результатов — повторный анализ не требуется
  • Экспорт XLSX и email-рассылка с AI-вердиктами
  • Планируется HTML-отчёт «Анализ причин неисправностей»
LLM · SQL-agent

Чат с базой данных

Руководитель задаёт вопросы на естественном языке — LLM формирует безопасные SQL-запросы (только SELECT), строит таблицы и графики. Без ручной выгрузки и без знания структуры БД.

  • «Сколько объектов с неисправными каналами в этом месяце?»
  • «Покажи топ-10 объектов по числу повторных РВР»
  • Автоматические графики ECharts по результатам запроса
  • Read-only доступ — запись в БД невозможна
