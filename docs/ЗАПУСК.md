# Запуск Wisenet Диагностика

Инструкция для локального запуска на любой машине. Путь к проекту может быть любым — все команды выполняются **из корня репозитория** (папка, где лежат `backend/`, `config.example.json`).

Примеры корня проекта:

- `D:\Projects\Wisenet Диагностика`
- `C:\Users\ivan\YandexDisk\Coding\Wisenet Диагностика`
- `/home/user/wisenet-diagnostics`

Далее этот каталог обозначается как **корень проекта**.

---

## Что нужно установить

| Компонент | Версия |
|-----------|--------|
| Python | 3.11 или новее |

Проверка:

```bash
python --version
```

Node.js и npm **не требуются** — веб-интерфейс отдаётся сервером (Jinja2 + HTMX).

---

## 1. Подготовка конфигурации

Перейдите в корень проекта и создайте рабочий конфиг из примера.

**Windows (cmd):**

```cmd
cd /d "ПУТЬ\К\КОРНЮ\ПРОЕКТА"
copy config.example.json config.json
```

**Windows (PowerShell):**

```powershell
Set-Location "ПУТЬ\К\КОРНЮ\ПРОЕКТА"
Copy-Item config.example.json config.json
```

**Linux / macOS:**

```bash
cd "ПУТЬ/К/КОРНЮ/ПРОЕКТА"
cp config.example.json config.json
```

Откройте `config.json` в редакторе и при необходимости укажите:

- `credentials.username` / `credentials.password` — учётная запись SUNAPI для всех NVR;
- `recorders` — список регистраторов (можно оставить пустым и добавить через UI).

> **Важно:** файл `config.json` не попадает в git (содержит пароли). На каждом компьютере его нужно создать заново или скопировать вручную.

Путь к конфигу по умолчанию: `config.json` в корне проекта. Чтобы указать другой файл:

```bash
set CONFIG_PATH=C:\путь\к\my-config.json
```

(Windows) или `export CONFIG_PATH=...` (Linux/macOS) — **перед** запуском сервера.

## 2. Запуск приложения

Нужен **один терминал**. Перейдите в каталог **`backend`** внутри корня проекта (где лежит `requirements.txt`).

> **Корень проекта** — папка **на уровень выше** `backend`: там же `config.json`, `config.example.json` и после запуска — каталог `logs/`.

### Windows (PowerShell), с venv

```powershell
Set-Location "ПУТЬ\К\КОРНЮ\ПРОЕКТА\backend"
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

### Без venv (если политика блокирует `python -m venv`)

Установите зависимости в профиль пользователя и запускайте так же из `backend`:

```powershell
Set-Location "ПУТЬ\К\КОРНЮ\ПРОЕКТА\backend"
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

Команда **`python -m uvicorn`** нужна, если `uvicorn` не в `PATH` (типично при установке через `pip` без venv).

### Windows (cmd)

```cmd
cd /d "ПУТЬ\К\КОРНЮ\ПРОЕКТА\backend"
python -m venv .venv
.venv\Scripts\activate.bat
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

### Linux / macOS

```bash
cd "ПУТЬ/К/КОРНЮ/ПРОЕКТА/backend"
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000
```

### Признаки успешного старта

Сразу после запуска в терминале должна появиться строка:

```text
Wisenet: логи -> C:\...\logs\wisenet.log
```

Если её **нет** — на машине старая копия кода **без** модуля `backend/app/logging_config.py`. Обновите проект (git pull / новый архив).

Проверка:

- [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health) — `{"status":"ok","log_file":"..."}` (путь к логу)
- [http://127.0.0.1:8000/objects](http://127.0.0.1:8000/objects) — веб-интерфейс

## 3. Первый вход в UI

1. Откройте **Настройки** (`/settings`) и сохраните логин/пароль SUNAPI (если не заданы в `config.json`).
2. На **Объектах** (`/objects`) добавьте регистратор: название объекта, host, порт.
3. Нажмите **Проверить** у строки NVR — статус обновится без перезагрузки страницы (HTMX).

Альтернативный вид — плоский список на **Регистраторах** (`/recorders`).

## Логи для диагностики

При запуске сервера создаётся каталог логов и файл **`wisenet.log`**:

1. **`WISENET_LOG_DIR`** — если задана переменная окружения (приоритет);
2. **`logs/` в корне проекта** (рядом с `config.json`);
3. **`backend/logs/`** — если в корень писать нельзя;
4. **`logs/` в текущей рабочей папке** — запасной вариант.

Пример своего каталога (PowerShell, перед запуском):

```powershell
$env:WISENET_LOG_DIR = "C:\Users\21204476\Documents\WisenetLogs"
```

Дублирование событий — в терминал, где запущен uvicorn.

Формат: одна строка = один JSON-объект. Пароли в лог **не попадают**.

После нажатия **Проверить** ищите события:

| `event` | Значение |
|---------|----------|
| `http_request` / `http_response` | Любой HTTP-запрос (есть ли `POST` на `/recorders/.../check`) |
| `check_start` | Кнопка дошла до бэкенда |
| `check_running` | Параметры NVR перед опросом |
| `sunapi_request` | Запрос к SUNAPI на устройство |
| `sunapi_check_done` | Итог опроса (статус, ошибка, `duration_ms`) |
| `check_done` | Ответ UI отправлен |

Пример (PowerShell) — последние 20 строк:

```powershell
Get-Content ..\logs\wisenet.log -Tail 20 -Encoding utf8
```

(из каталога `backend`; путь к логу: `../logs/wisenet.log` относительно `backend`.)

Для разбора проблемы пришлите фрагмент лога с момента нажатия **Проверить** (10–30 строк).

## Частые проблемы

| Симптом | Что проверить |
|---------|----------------|
| Страница не открывается | Запущен ли сервер: `python -m uvicorn ...` на порту 8000 |
| Нет папки `logs`, нет строки `Wisenet: логи ->` | Обновите код; проверьте `/health` — есть ли поле `log_file` |
| `uvicorn` не найден | Используйте `python -m uvicorn app.main:app --reload --port 8000` |
| venv заблокирован политикой | Запуск без venv (см. выше), `pip install -r requirements.txt` |
| «Проверить» — статус «Не проверялся», в логе нет `POST .../check` | HTMX не работает: в логах все запросы с `"htmx": false`. Нужна свежая версия с локальным `/static/js/htmx.min.js` (без CDN) |
| «Проверить» — в логе есть `check_start` | Смотрите `sunapi_check_done` (сеть, credentials, NVR) |
| Проверка NVR — «Не заданы учётные данные» | Настройки UI или `credentials` в `config.json` |
| Проверка — 401 | Логин/пароль SUNAPI на устройстве |
| Проверка — таймаут | Доступность host:port с этой машины, firewall |
| PowerShell не даёт активировать venv | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
